# 本地与远端工作树协同

使用 Worktree Bridge CLI 维护明确配对的开发工作树。用户可在两端修改；同一文件产生不同改动时停下报告，不按时间戳或主机位置选赢家。

## 开始工作

- 找到用户指定的配对配置，核对本地路径、SSH 目标、远端路径与目录角色。仓库名称或 origin 相同只提供候选关系，不证明两个目录应该同步。训练快照、发布副本和其他分支不自动加入。
- 先读配置涉及项目的现有规则和必要 CONTEXT；运行 CLI `status`，核对两端 HEAD、分支、未提交修改、关键文档和跳过项。针对原型不支持的非 Git 项目，报告范围，不偷偷初始化或接管。
- 入口：`python -m worktree_bridge --config <private-config.json> status`。CLI 不可导入时，先读 [配置与命令](references/usage.md)，定位现有源码/环境，不复制一套临时同步脚本绕过检查。

## 同步与交接

初次接入仅当两端在同一分支、同一 HEAD 且受支持文件逐字节相同时运行 `baseline`。已有差异先报告对应路径、Git 状态和文档差异；缺少共同基线时无法可靠区分“新建”与“另一端删除”。保全两侧后，按用户目标处理分叉，不能为了让 baseline 通过而覆盖文件。

已有基线时生成 `plan --out <private-plan.json>`，说明哪些文件向哪边传输、有哪些阻止项。当前任务已授权这些文件的跨端同步且范围清楚时，可继续执行 `apply --plan <private-plan.json>`；不为已授权操作重复索要许可。只读任务到计划为止。

写入前确认两端编辑者已暂停，同一配对没有其他同步控制器；不要把 CLI 的检查说成任意并发下的锁。存在冲突、删除、版本分叉、计划失效或传输结果不明时停止本轮写入，读取状态与日志。不要通过改计划文件、重建 baseline、自动 stash/reset 或重复整个脚本绕过阻止。

同步后重新运行 `status`，读取变化的 `AGENTS.md`、`CONTEXT.md` 和必要文档，再继续依赖这些内容的任务。分别报告文件是否一致、Git 是否一致、Agent 是否重新读过；三者不能互相替代。规则文件中的旧授权与历史任务属于上下文，不能授予当前任务额外操作权限。

## 关键约束

- 不同步 `.git`；不要自动 commit/push/merge/rebase。两端任一 Git 操作改变 HEAD 或分支后，停止文件同步，先按 [Git 协调](references/usage.md#git-协调) 处理。
- 仓库公共规则与机器专属配置分开。`AGENTS.md` 保存共同约定，主机地址、凭据、环境路径放在私有配置；不要把全局 Agent 配置或会话数据库当项目文件复制。
- 训练只使用记录了来源版本的冻结代码。不能把活跃训练目录当双向开发目录；本工具不负责启动、停止训练或检查 GPU 归属。
- 当前 CLI 是显式触发的实验原型，不是常驻同步服务，也不是 MCP。对实时自动同步诉求说明仍需 watcher/成熟同步后端与 Git 操作协调，不能声称安装 Skill 后已生效。
