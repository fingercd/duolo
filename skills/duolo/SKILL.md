# Duolo：本地与远端工作树协同

使用 Duolo 0.4 的已注册配对与后台服务，查询文件、Git 和连接状态；同一文件两端不同修改时报告冲突，不按时间戳或主机位置选择赢家。

主命令为 `duo`，Python 包与模块为 `duolo`。旧配对的存储目录和本机协议保留兼容；定位配置时按返回值和[配置与命令](references/usage.md)操作，不因改名搬动基线或状态目录。

## 进入项目

- 先读项目现有规则和必要 `CONTEXT.md`，核对用户指定的目录角色。共享 origin 或同名目录只是候选关系，训练快照、其他分支和旧副本不自动加入。
- 在仓库内运行 `duo status`；默认读缓存，核对实际观察时间、两端 HEAD/分支、待处理变化、冲突与错误。未注册或未启动时明确报告，不在只读任务中自动注册、启动或覆盖文件。
- 需要注册、迁移、全量检查或 CLI 环境定位时读 [配置与命令](references/usage.md)。`init` 只注册，`start` 才启用后台策略；已有不一致须先保全整理，不能通过建立基线选一端覆盖。

## 同步与交接

已有服务会观察两端变化并按共同基线同步；不要求每次保存都由 Agent 调用。当前任务授权允许同步时，可用 `sync` 请求立即处理，再用 `wait` 确认新一轮观察。`queued: true` 不是完成；`wait` 只核对，不传输或绕过暂停。只读任务使用状态、等待或显式全量检查，保持只读。

出现文件冲突、Git 阻止项、离线、过期选择或结果未知时，读取状态与持久记录，再决定后续。冲突选择需审阅两端内容并携带当前 revision；不改计划/基线、盲目重放、自动 stash/reset 或自动合并来绕过阻止。详细 Git 和恢复边界见 [Git 协调](references/usage.md#git-协调)与[失败恢复](references/usage.md#失败恢复)。

成功后重新读取变化的 `AGENTS.md`、`CONTEXT.md` 和必要文档。分别报告文件是否一致、Git 是否一致、Agent 是否重读；文档到达磁盘不能替代实际重读。旧授权和历史任务只是上下文，不提供额外操作权限。

## 关键边界

- 自动 Git 只受保护地跟进已有 commit，不每次保存自动提交、不发布项目。显式 `checkpoint` 可创建本地 commit/tag，不运行 commit hooks；是否允许提交由本轮授权与项目规则决定。
- 不复制 `.git`、全局 Agent 配置、会话数据库或凭据。机器专属配置与公共项目文档分开。
- 训练使用固定版本快照，活跃训练目录不作同步目标；本工具不负责 GPU、训练启停或数据迁移。
- 单文件原子写不等于跨主机事务；控制器锁不能约束任意编辑器或 Git 进程。需要手动分叉处理时暂停服务并保全工作，旧 `apply` 不与运行服务同时写入。
